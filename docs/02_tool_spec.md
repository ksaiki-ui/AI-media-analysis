## 1. 要件の整理（ユーザー案 → 仕様への翻訳）

| ユーザー案 | 仕様での扱い | 補足・修正点 |
|---|---|---|
| メディアURLにアクセスし全体をクローリング | **sitemap.xml ベースの記事棚卸し**（上限500URL） | 順位・KWは**クローリングでは取れない**。クロールの役割は「記事数・タイトル・公開日の把握」に限定。全ページのHTML取得は不要 |
| 記事ごとの順位・ランクインKW | SEOデータAPI（DataForSEO Labs `ranked_keywords`）で取得 | 日本（location: Japan / language: ja） |
| 検索Volからセッション数を推定 | 推定セッション = Σ 検索Vol × 順位別CTR | CTR表は資料p.4と同じ出典（Keywordmap採用CTR）で統一。**レンジ表示** |
| 競合3〜5社を特定 | 自動候補抽出（SERP重複）→ 除外リスト → LLMで事業類似度判定 → 上位3社 | ユーザー指定があれば優先。**MVPは3社固定**（5社は情報過多・原価増・QA負荷増） |
| テーマ（クラスター）単位の分析 | KWをクラスタリングし、クラスター × ドメインで推定セッションを集計 | 全ドメイン共通のクラスター軸で並べるのが肝（比較可能にするため） |
| PDFでメール送付 | **Webビューワー（トークン付きURL）＋ PDF DL** をメール送付 | 閲覧トラッキングで架電タイミングを判断 |

## 2. システム構成

```
[LP / フォーム] ──POST──▶ [API: 申込受付]
                              │ バリデーション・悪用フィルタ
                              │ CRM登録（HubSpot/kintone等）・Slack通知
                              ▼
                         [ジョブキュー]（SQS 等）
                              │
                              ▼
┌──────────────────── 解析ワーカー ────────────────────┐
│ S1 ドメイン正規化・メディア領域の特定                   │
│ S2 記事棚卸し（sitemap / robots.txt 遵守）             │
│ S3 自社ランクインKW取得（SEO API）                      │
│ S4 競合候補抽出 → フィルタ → 3社確定                     │
│ S5 競合のランクインKW取得・記事棚卸し                    │
│ S6 KW正規化・クラスタリング（共通軸）                    │
│ S7 指標計算（推定セッション・KW分布・記事効率）           │
│ S8 メディア特性判定・所見生成（LLM, 数値は S7 のみ参照）   │
│ S9 レポート組版（HTML）→ PDF化（Playwright/Chromium）    │
└───────────────────────────────────────────────────────┘
                              │
                              ▼
                    [QAキュー（MVPのみ）] ── 営業/担当が確認・修正・承認
                              │
                              ▼
         [メール送付（SES等）: Webビューワーリンク + PDF]
                              │
                              ▼
     [閲覧イベント] ──▶ CRM更新・Slack「◯◯社がレポートを閲覧（p.4 市場地図 に2分）」
```

既存の AIメディアくん（kwlab）が KW取得・クラスタリングを持っていれば **S3・S6 は共通モジュール化**する。診断で作ったクラスターを、受注後のメディアプランニング初期値にそのまま引き継げると、「診断の続きから始まる」体験になる（オンボーディング短縮）。

## 3. 処理ステップ詳細

### S1. ドメイン正規化・メディア領域の特定
- 入力URLからホストを抽出（`www.` 正規化、リダイレクト追跡）
- メディアの形態を判定:
  - サブドメイン型（`media.example.co.jp`）
  - サブディレクトリ型（`example.co.jp/column/`）
  - コーポレートサイト全体
- サブディレクトリ型の場合、以降のKW集計を **URLプレフィックスでフィルタ**（コーポレートページの指名KWが混ざると「メディアの実力」を過大評価するため）
- **指名KWの除外**: 会社名・サービス名を含むKWは別枠集計（メディア成果ではない）

### S2. 記事棚卸し
- `robots.txt` を取得・遵守 → `sitemap.xml`（index含む）から URL と `lastmod` を取得
- sitemapが無い場合: トップ＋一覧ページから最大2階層・最大200URLを辿る
- 上限500URL、1リクエスト/秒、UAに連絡先を明記
- 取得するのは **URL・title・h1・公開/更新日** のみ（本文は保存しない）
- 出力: 記事数、月別公開本数（更新頻度）、最終更新日

### S3. ランクインKW取得
- DataForSEO Labs `ranked_keywords`（Google / Japan / ja）
- 取得条件: 順位 ≤ 50、推定流入降順で上位 1,000件（ドメインあたり）
- 各KW: keyword, search_volume, rank, ranking URL, SERP特徴（AI Overview有無など）
- **自社モード判定**: メディア領域の ランクインKW（順位≤20・指名除外）が 30 未満 → **参入診断モード**

### S4. 競合の特定
1. 候補抽出: `competitors_domain`（KW重複度順）上位30ドメイン
2. 除外: 汎用大手（wikipedia, youtube, amazon, note, prtimes, 大手ニュース/ポータル等）の固定リスト
3. 事業類似度: 候補のトップページ title/description と自社の同情報をLLMに渡し、「同じ顧客に同じ種類の価値を提供しているか」を0〜1で判定
4. スコア = KW重複度 × 事業類似度 → 上位3社
5. ユーザー指定がある場合は指定を優先し、足りない分を自動で補う
6. **参入診断モード**では自社KWが少なく重複が取れないため、代替として「自社サービス説明から生成したシードKW群のSERP上位ドメイン」から抽出

### S5. 競合の取得
- S2・S3 を競合3社に対して実行（サブディレクトリ判定も同様）

### S6. クラスタリング（ここが品質の肝）
- 全4ドメインのKWを **1つのプール** にまとめ、共通のクラスター軸を作る
- 手順:
  1. KW正規化（全角半角・表記ゆれ・語順）
  2. 埋め込みベクトルで一次クラスタリング（目安 8〜15クラスター）
  3. LLMでクラスター名付け＋検索意図タグ付け（`知りたい` / `比較検討` / `今すぐ依頼` など）
  4. 小さすぎるクラスター（推定セッションが全体の1%未満）は「その他」に統合
- 将来: SERP重複（同じURLが上位に出るKWは同クラスター）での精緻化

### S7. 指標計算

| 指標 | 定義 | 備考 |
|---|---|---|
| 推定月間セッション | Σ(search_volume × CTR(rank)) | CTR: 1位35%、2位19%、3位12%…10位1.5%、11位以降は逓減。**±幅つきで表示**（下記） |
| ランクインKW数 | 順位帯別（1–3 / 4–10 / 11–20 / 21–50） | 「惜しいKW（11–20位）」は面談ネタ |
| 記事数 | S2 の記事URL数 | |
| 1記事あたり推定セッション | 推定セッション ÷ 記事数 | メディアの“効率”。少数精鋭型か量産型かの判定材料 |
| クラスター別シェア | クラスターごとの各社推定セッション比率 | 市場地図の元データ |
| 検索意図構成比 | 意図タグ別の推定セッション比 | 集客型か刈り取り型かの判定材料 |
| 上位記事 | 記事URL別の推定セッション TOP10、主要KWと順位 | |
| 機会の大きさ | 競合合計が大きく自社が小さいクラスターの、競合最大値 − 自社値 | **「何を書くか」ではなく「どれだけ取れていないか」だけ出す** |

**推定値の表示ルール**
- 絶対値は丸める（例: 12,340 → 「約1.2万」）＋レンジ（×0.6〜×1.5 を目安、実測で調整）
- 全ページのフッターに「サードパーティの検索データからの推定値であり、実際のアクセス数とは異なります」
- 比較（シェア・順位・KW数）を主役、絶対値は脇役

### S8. 所見生成（LLM）
- 入力は **S7 の集計JSONのみ**（生データやWebを参照させない）
- 出力:
  - サマリー: 発見3点（各80字以内）
  - 各社の **メディア戦略タイプ** 判定と根拠（例: 用語解説型 / 比較検討型 / 事例・一次情報型 / ニュース型 / 量産ロングテール型）
  - クラスターごとの一言コメント
- ガードレール:
  - 文中の数値は集計JSONに存在する値のみ（生成後に数値照合し、不一致なら再生成）
  - 改善指示・断定的な評価（「劣っている」「失敗している」）は禁止。**競合への否定的表現も禁止**（第三者の評価を配布するため）
  - 「次に書くべき記事」は出力しない（面談で提示）

### S9. 組版・PDF化
- HTMLテンプレート（AIメディアくんのブランドに統一）→ Chromium で PDF（A4横 10ページ前後）
- Webビューワーは同じHTMLをトークン付きURLで配信（有効期限90日、noindex）

## 7. 申込バリデーション（悪用対策）

| チェック | 動作 |
|---|---|
| フリーメール（gmail, yahoo 等） | 拒否 |
| メールドメイン ≠ 解析ドメイン | 生成はするが **QA必須**（自動送付しない） |
| 同一ドメイン30日以内の再申込 | 既存レポートを再送 |
| 除外リスト（代理店・競合） | 保留 → 担当判断 |
| bot | Turnstile / reCAPTCHA |
| 月間上限 | 上限超過時は「来月枠のご予約」表示 |

## 8. QA（MVP）

担当者が承認画面で確認する項目（1件10分以内を目標）:
1. 競合3社は妥当か（差し替え可能）
2. メディア領域の判定（サブディレクトリ）は正しいか
3. クラスター名は自然か（編集可能）
4. 所見に不適切な表現がないか
5. 架電メモ（面談で出すテーマ案の当たり）を記入 → CRMへ

**Phase 2 での自動送付条件（案）**: 競合の事業類似度がすべて0.7以上、クラスター数が8〜15、数値照合エラー0、メールドメイン一致。

## 9. 原価試算（1レポート）

| 項目 | 前提 | 目安 |
|---|---|---|
| ランクインKW | 4ドメイン × (0.012 USD/task + 1,000件 × 0.00012 USD) | 約0.53 USD |
| 競合候補 | 1〜2 task | 約0.05 USD |
| LLM（事業類似度・命名・所見） | 数万トークン | 数十〜百円程度 |
| 埋め込み | 4,000KW | 数円 |
| 合計 | 2026年7月の価格改定（約+20%）を考慮しても | **1件あたり数百円程度** |

※ DataForSEO の単価は検索結果時点の情報。実装前に最新の料金表・**データを第三者（見込み客）向けレポートに載せる際の利用規約**を確認すること。代替: Ahrefs API（Lite $129/月〜、ユニット制）、Semrush API（Advanced $549/月＋ユニット別購入）。月100件規模なら従量課金の DataForSEO が有利。

**本当のコストは人件費**: QA 10分 ＋ 架電 ＋ 面談30分。

## 10. 非機能・法務

- 処理時間: 1件 3〜10分（API待ち含む）。MVPは QA を挟み1営業日以内送付
- クロール: robots.txt 遵守、1req/s、本文非保存、UA明記
- 個人情報: プライバシーポリシー同意、利用目的（レポート送付・サービス案内・架電）明記
- 特定電子メール法: 営業メール送信の同意取得、配信停止リンク
- 第三者ドメインの情報: 公開情報からの推定である旨の注記、否定的評価の禁止
- Webビューワー: noindex、トークンURL、期限付き
