### v1 → v2 の主な変更
1. **ファーストビュー**: 「毎月30社限定／完全無料／メディアがなくても可」のバッジ、成果物スペック3点、オレンジのCVボタン（緑基調の中でCVだけ目立たせる）
2. **数字の帯**: 3社／8〜15テーマ／8本／5つ
3. **「こんなお悩み、ありませんか？」**: 6項目のチェックリスト → 「その判断材料を、同業との比較で1本のレポートに」
4. **「この診断でわかる5つのこと」**: 番号＋説明＋小さな図（どちらの診断で分かるかのタグ付き）
5. **中間CTA帯**を追加
6. **比較表「一般的な無料SEO診断との違い」**: 即時診断ツール／コンサル個別診断／本診断の3列。**即時性・登録の手軽さでは劣ると正直に示す**（全項目◎の比較表は信用されない）。特定サービス名は出さない
7. **サンプルレポート**: 4ページ分のサムネイル＋両診断の目次
8. **「なぜ、無料なのか」**: 無料の理由（メディアプランニングのお試し）＋資料の自社検証データ（品質スコア80→88→92）を実績の代わりに
9. **注意事項を3つに**: 推定値／記事ごとの指示は含まない／月30社の理由（担当者が1件ずつ確認するため）
10. フォームに受付上限の表示、SSL表記、完了画面に「この後の流れ」

### 注意（寄せ方の線引き）
- 参考LPのページ本体は作業環境のネットワーク制限で閲覧できず、**検索結果に出る文言・構成のみを参照**した。配色・画像・レイアウトの細部は各LPを直接確認して詰めること
- 寄せたのは**構成と型**であり、文言・デザインの複製はしていない（著作権・不正競争のリスク回避、および最も近いferretと見分けがつかなくなるのを避けるため）
- 「毎月30社限定」は、**実際の対応上限と一致させること**。根拠のない限定表記は景品表示法上の有利誤認のリスクもある

## 1. 基本方針

| 論点 | 決め | 理由 |
|---|---|---|
| LPの本数 | **1本** | 運用・計測を1本に集約する。流入元ごとの訴求はURLパラメータで差し替える |
| ファーストビューの見出し | 2つの診断の**共通の問い**「同業は、記事から毎月どれだけ集客しているか」 | 「運用中」「これから」の両方に効く問い。2つの商品名を見出しに並べると、どちらにも刺さらない |
| 診断の選び方 | **LPでは選ばせない**。フォームの「メディアの状況」1問で振り分ける | 商品選択は離脱の原因になる。実データで補正する前提（03_report_design.md §2） |
| 広告別の訴求 | `?type=entry`（未開設向け）/`?type=improve`（運用中向け）で見出し・説明文・状況の初期選択を差し替える | LPを分けずに、広告のキーワードと見出しを一致させられる |

## 2. ページ構成

| # | セクション | 役割 |
|---|---|---|
| 1 | ヒーロー（URL入力つき） | ファーストビューでURLを入れさせる。入力値は下のフォームに引き継ぐ |
| 2 | WHY：判断する材料がない | 3つの悩み（やる意味／何から／伸びない）。2つの層の両方の悩みを並べる |
| 3 | REPORT：2種類のどちらかをお届け | 参入診断／改善診断の中身。**「選ぶ必要はない」と明記** |
| 4 | SAMPLE：レポートの中身 | 広告換算額・テーマ地図・スタートKW・同業比較の4点＋サンプルレポートへのリンク |
| 5 | FLOW：申込から届くまで | 1営業日・担当者確認・30分の解説（ここで架電を予告する） |
| 6 | NOTE：あらかじめお伝えしておくこと | **推定値であること、記事ごとの改善指示は含まないこと**を先に言う（期待値の調整） |
| 7 | ABOUT：AIメディアくん | 診断＝メディアプランニングのお試し、という位置づけ |
| 8 | FAQ | 無料か／メディアがなくても可か／競合の決め方／営業電話／他社サイト／代理店 |
| 9 | フォーム（2ステップ） | 下記 |

## 3. フォーム

- **Step 1（サイトの情報）**: URL・メディアの状況（まだない／止まっている／運用中）・主なサービス（運用中以外は必須）・比較したい会社（任意）
  - 状況を選ぶと、**届く診断の種類がその場で表示**される（「止まっている」は、流入が残っていれば改善診断、と説明）
- **Step 2（ご連絡先）**: 会社名・氏名・会社メール（フリーメール拒否）・電話（「解説のお電話をする場合があります」と明記）・同意チェック
- **完了**: メールのドメインと診断するサイトが違う場合は「確認のご連絡をする場合があります」と表示（悪用対策の審査フローに乗せる）

## 4. 計測（実装時）

| イベント | 目的 |
|---|---|
| ヒーローURL入力 → フォーム到達 | ファーストビューの効き |
| Step 1 完了率 / Step 2 完了率 | どちらのステップで落ちているか（電話番号の必須化の影響を見る） |
| 状況の選択比率（none / stopped / active） | 想定リード構成の検証（01 §5 の確認事項1） |
| `type` パラメータ別の申込率 | 広告訴求の比較 |
| サンプルレポートの閲覧 → 申込 | サンプル公開の効果 |

## 5. 未決事項・懸念

1. **電話番号の必須化**: Step 2 の完了率を見て、任意化のA/Bテストを検討する
2. **「月30社まで」の表記**: 実際の架電・面談のキャパから決める。数字が根拠のない煽りにならないよう、実際の上限と一致させる
3. **ABOUTの数字**: サービス資料の数値（13エージェント・1.5万円・20分・週2×30分）を転記。実績（導入社数など）が出たら差し替える
4. **ヒーロー右のレポート画像**: 現在はCSSで描いたイメージ。実装時は実際のサンプルレポートのスクリーンショットに差し替える方が信頼感が出る
